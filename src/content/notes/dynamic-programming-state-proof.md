# 动态规划：状态设计与证明

> 本文为学习笔记整理。示例用于说明概念，性能、版本兼容与平台行为需结合实际环境验证。

## 核心结论

动态规划的核心是把具有重叠子问题和最优子结构的问题，定义成“状态代表什么”，再写出从更小状态到当前状态的转移、初始条件和遍历顺序。复杂度来自状态数量乘以每个状态的转移成本，而不是看到二维数组就叫 DP。

## 四步推导

1. **状态语义**：`dp[i]`/`dp[i][j]` 必须能用一句完整的话定义。
2. **最后一步**：枚举导致当前状态的最后选择，推导转移。
3. **边界与不可达**：区分合法的 0、无穷大、负无穷和未计算。
4. **遍历与压缩**：依赖方向决定循环顺序；只有证明旧状态不再需要时才滚动数组。

## 将递推写成证明义务

设原问题在输入规模 `n` 上的答案为 `OPT(n)`。一个 DP 定义不是“准备一个数组”，而是建立 `dp[s]` 与某个子问题最优值/计数之间的等价关系。每个转移要证明：

1. **soundness**：转移生成的每个候选都对应原问题的合法方案。
2. **completeness**：任意最优合法方案都能由至少一个枚举的前驱和最后选择生成。
3. **optimal substructure**：固定最后选择后，前缀/子区间用最优子解替换不会变差。
4. **evaluation order**：计算 `dp[s]` 前，所有依赖状态已经算好。
5. **base case**：最小状态与原问题含义一致，而非为了让代码不报错随手填 `0`。

如果只证明 soundness，可能漏掉更好的方案；只证明 completeness，可能把非法方案计入。算法说明应同时覆盖两面。

## 例：0/1 背包的状态和循环方向

有 `n` 个物品，物品 `i` 的重量 `w[i]`、价值 `v[i]`，容量为 `W`，每件最多取一次。定义：

```text
dp[i][c] = 只考虑前 i 件物品、容量至多 c 时可获得的最大价值
```

考虑第 `i` 件：不取则为 `dp[i-1][c]`；取（要求 `c >= w[i]`）则为 `dp[i-1][c-w[i]] + v[i]`。因此转移是两种互斥且穷尽的最后选择的最大值。边界 `dp[0][c]=0`，因为没有物品时任意容量的最优价值为 0。

压缩第一维时，一维数组 `dp[c]` 复用上一行。容量必须逆序：

```text
for each item i:
    for c from W down to w[i]:
        dp[c] = max(dp[c], dp[c - w[i]] + v[i])
```

逆序保证右侧 `dp[c-w[i]]` 尚未被当前物品更新，仍代表 `i-1` 件物品；正序会允许本轮刚写入的状态再次作为前驱，从而把同一件物品重复使用。完全背包恰好相反：物品可重复，容量正序使当前物品可被再次使用。这不是记忆技巧，而是压缩后依赖版本的证明。

## 状态图与拓扑顺序

把状态看成有向图：边 `p -> s` 表示 `dp[s]` 依赖 `dp[p]`。常见 DP 是 DAG 上的最短路、最长路、计数或半环聚合。循环顺序必须是这个状态图的拓扑序；若依赖存在环，普通一次遍历不成立，要改成固定点算法、最短路或重新定义状态。

| 结构 | 依赖关系 | 遍历顺序 | 典型失误 |
| --- | --- | --- | --- |
| 前缀 DP | `i` 依赖更小 `i` | 从左到右 | 忘记空前缀 base case。 |
| 0/1 背包压缩 | 本轮依赖上一轮 | 容量逆序 | 同一物品被重复用。 |
| 完全背包压缩 | 本轮可继续依赖本轮 | 容量正序 | 错误逆序导致变成 0/1。 |
| 区间 DP | `[l,r]` 依赖更短区间 | 长度递增 | 依赖尚未计算的区间。 |
| 树形 DP | 节点依赖子树 | 后序/DFS 返回 | 合并子树时状态语义混乱。 |
| DAG 路径 DP | 节点依赖拓扑前驱 | 拓扑序 | 把存在环的图当 DAG。 |

滚动数组只在旧状态最后一次使用后才能覆盖。若要求恢复方案，必须另外存 parent/choice、保留关键层，或第二次重算；只留下最优数值一般无法唯一推出最优决策。

## 常见边界

- 0/1 背包容量循环通常逆序，防止同一物品在一个阶段重复使用；完全背包通常正序。
- 区间 DP 的长度从短到长，确保子区间已计算。
- 需要恢复方案时保存 choice/parent，不能只保留最优值。
- 负权、环、无限状态和概率转移可能不适合普通 DP，需要图算法/最短路/记忆化或数学推导。

### 不可达值与数值范围

最小化问题常用 `INF` 表示不可达，但 `INF + cost` 可能溢出。选择小于上限的 sentinel 并在相加前检查，或使用更宽类型/可选值。最大化问题也要区分“不可达”与合法答案 `0`、负值；如果所有选择都可能为负，初始化为 `0` 会悄悄允许空方案。

计数 DP 还需说明计数对象和模数：按序列计数还是集合计数、不同顺序算不算不同、重复元素是否区分。状态相同不意味着组合唯一；循环顺序可能改变计数语义。

### 最优值和可行性是不同问题

布尔可行性、最优值、最优方案数量和恢复一个方案可能共享状态，但转移聚合不同：OR、min/max、sum 不能混用。若只求最小值，用 `min` 聚合前驱；若数最优方案，应先找到最优值，再只对达到最优值的前驱求和。把所有可行前驱相加会算成“所有方案数”。

### 状态设计的取舍

状态太粗会丢失未来决策需要的信息；状态太细会指数膨胀。判断标准不是变量有几个，而是两个历史前缀若映射到同一状态，是否对所有未来选择具有相同的合法后续和增量。若不能，它们不应合并。背包容量、最后颜色、持有/冷却状态、区间端点等都是在压缩历史时保留未来相关信息。

滚动优化复杂度时先保留二维版本作为可读 oracle。确认状态不变量与循环方向后，再改为一维；否则优化会同时改变状态可见性和证明对象，排错更困难。

## 复杂度与可行性估算

时间复杂度通常是“可达状态数 × 每状态候选转移数 × 每次转移代价”，空间复杂度是实际保留的状态、重建信息和递归栈。写出大 O 后还要代入约束：`O(nW)` 的背包是伪多项式；若 `W` 可达 `10^9`，它并不因看似多项式就可运行。稀疏状态可用 map/压缩，但哈希常数、状态去重和内存上限要计入。

## 验证

对小规模输入用暴力枚举全部选择作 oracle；随机测试状态边界和恢复路径。写出不变量：每个 dp 值代表什么、转移是否覆盖所有最后选择且没有重复计数。

建议验证矩阵：

| 测试 | 目标 | 例子 |
| --- | --- | --- |
| 空输入/最小维度 | base case 定义正确 | 0 件物品、空字符串、单节点。 |
| 恰好贴边 | `<=`/`<`、容量边界 | 重量正好 `W`、区间长度 1。 |
| 不可达状态 | sentinel 不参与错误转移 | 目标容量不能凑、图节点不可达。 |
| 负值/零值/重复值 | 初始化与计数语义明确 | 全负价值、零权值、重复字符。 |
| 小随机输入 | 与穷举/递归 oracle 对照 | `n <= 20` 时枚举所有子集。 |
| 恢复方案 | 方案合法且其目标值等于 DP | 重放 parent/choice 并重新计算。 |
| 压缩前后对照 | 优化实现与二维基准完全一致 | 随机测 0/1 和完全背包。 |

对于最大化/最小化 DP，比较最终目标值还不够：恢复出的方案必须满足原始约束且重新算出的成本与答案一致。随机测试应固定并输出 seed，失败时保存最小化后的反例。
